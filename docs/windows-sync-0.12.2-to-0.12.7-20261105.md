8. 本文“已通过”均指注明日期、平台和范围的历史验收。此次只整理文档和源码差异，没有重新执行整套构建或 NAS 全库处理。

## 4. NAS 路径处理：详细需求与已实现行为

### 4.1 根因与边界

曾出现目录能列出韩文、日文浊音、重音字母文件名，但 Mac SMB 挂载路径打开返回 ENOENT。Qt、系统访问、原始名称、NFC/NFD、相对目录描述符访问均做过定点核查。**不能归纳为“软件不支持韩语”，也不能默认 normalize 一次就能解决。**

服务端原始文件名、客户端挂载层名称转换、同名候选、原件是否存在、索引版本是否过时、内容是否为空，都会造成不同结果。Windows 可能原本就能读取同一文件；不要看到某种语言就强制修复。

### 4.2 产品入口与批量对象

- 入口在“设置 → 波形缓存 → 异常详情与重试 → 批量处理路径问题…”。
- 从当前索引和去重异常中选择路径访问失败对象，首要对应 `source_unavailable`；已有兼容文件不可用也需分类处理。
- 不把纯解码错误、空音频、磁盘写满一概加入路径修复。
- 显示当前文件、进度和成功/失败原因，区分硬链接、本地缓存、既有映射复用。
- 保留检查点；暂停安全结束当前操作后停，重启后可恢复。重新获得会话时继续原模式及游标。
- 不通过外部零散脚本在 NAS 个人目录不断新建测试库。

### 4.3 处理顺序

1. 正常可用的原件保持原读取方式。
2. 对需要处理的 NAS 路径，获取服务端真实名称，逐级匹配，保留原始名称用于服务端访问。
3. 尝试在同一 NAS 文件系统、独立兼容目录中建立硬链接。
4. 硬链接不支持、跨文件系统、权限不允许或建立后仍不可读时，使用独立本机缓存保存该异常文件。
5. 验证内容与原件一致，写入与原索引版本绑定的兼容映射。
6. 重试原来的波形任务；**建立映射成功不等于波形成功**。
7. 仍失败则保留错误和已有有效波形，按单文件或批次级原因决定继续/暂停。

早期 0.12.3 曾提供 NAS 兼容副本流程；0.12.4 起用户选择的主路线是“硬链接优先，异常文件本地缓存兜底”。Windows 应实现最终路线，不要重新把全库复制作为默认方案。

### 4.4 硬链接规则

硬链接是同一份文件内容的另一个目录入口，不是完整副本。创建很快不代表整个任务无成本：还包括服务端列目录、属性读取、网络传输、完整校验和解码。

- 只能在服务器允许的同一文件系统范围内建立。不要把客户端支持硬链接等同于远端 NAS 支持。
- 使用已有 SMB 服务，不新增 SSH/NAS 服务，不依赖外部 Python 或命令行密码。
- 独立兼容目录不能落入原素材根、其他素材库或共享波形目录。
- 原文件和硬链接使用 fresh stat 核对 fileId、大小、mtime、链接信息；不能只信列表返回的可能为 0 的链接数。
- 对硬链接不执行内容编辑、权限/所有者改写等会影响原 inode 的操作。
- 不覆盖已有文件；临时文件清理只涉及本工具明确创建、可确认归属的未完成项。
- 合法硬链接会改变链接数，可能影响 ctime；不能承诺所有元数据绝对不变。音频字节、原路径和必要版本信息必须有证据。

### 4.5 原件、兼容文件和索引

新增 `compatible_sources` 映射。索引 schema user_version 仍为 6，未以升级为由重建数据库。

- `Track::absolutePath()` 代表原件；`sourcePath()` 可返回有效兼容来源。
- 映射绑定 library、relativePath、原根、原 size/mtime，保存兼容路径、大小、mtime、SHA-256。
- 不改 track ID、library ID、原相对路径、收藏、标签。
- 原件版本变化、映射失配或兼容来源验证失败，不得继续静默复用旧映射。
- 波形身份仍绑定原索引版本；不能把副本的 mtime 当成原件 mtime。
- 兼容来源生成的波形不直接作为可跨机器复用的完整共享波形发布。
- “复制原路径”“在文件管理器中显示”、明确的原件删除操作，不能被兼容来源偷偷替换。
- 拖出经过验证的兼容来源时，要保留来源区别；不要把它伪称为原始路径。

### 4.6 文件名消歧（0.12.6）

规范化后名称相同不代表同一个文件。只能在**最终文件叶子节点**满足以下条件时自动选择：

- 已索引大小是有效正值，具有可比较的版本元数据；
- 所有规范化同名候选都完成新的属性读取；
- 只有一个候选与已索引 size/mtime 一致；
- 再次列目录和检查属性确认候选集合与版本稳定。

中间目录歧义、未知属性、不可读候选、多个匹配、检查期间新增候选/版本变化，继续拒绝自动选择。不能拿“第一个结果”“最相近名字”“较大文件”猜选，也不能用另一个同名 FLAC 自动替换索引 MP3。

### 4.7 连接和依赖

- 早期 UGOS Pro HTTP 接口与原生 SMB 后端代码均保留；接口调用、加密和连接选择以最终源码为准。
- libsmb2 固定上游提交 `727feaaa6d0f4fed1bae57745fbc2c5db9a30e64`。本地小补丁通过 `SMB2_RUNTIME_CREDENTIALS_ONLY=1` 禁止隐式读取 NTLM_USER_FILE 凭据文件；不是协议加密修改。
- 当前构建关闭不需要的 Kerberos/GSSAPI、示例与工具，C 库关闭 AUTOMOC。
- 凭据仅在父进程/会话运行时使用，不写入日志、检查点、索引、环境变量或子解码任务参数。
- 会话需重连时由产品流程处理，不通过写死账号绕过。
- 第三方许可证、来源和再链接说明见 `application/docs/macos-third-party.md` 及 libsmb2 自带许可证。Windows 打包需保留适用材料；不要只拷贝库文件而漏掉说明。

## 5. 校验优化、队列与音频消费

### 5.1 首次完整校验，未变化不重复读取整曲

入口：`verifiedMediaPath`；持久化凭据库：profile 下 `media-verification.sqlite`。未指定持久化位置时使用有界的进程内缓存。

完整校验成功且前后身份稳定，才写入凭据。当前 Unix 指纹含 device/inode、size、纳秒 mtime/ctime，同时绑定预期 SHA-256 和路径。

- 同一有效文件身份不变时，播放、拖出、波形和应用重启可复用校验凭据。
- 文件替换、相同大小的内容变更、时间/身份变化、预期哈希变化，重新完整校验。
- 凭据丢失、损坏、不可写或文件系统没有可靠身份，退回完整校验；不能直接跳过。
- 同一文件并发核验去重，不用全局大锁串行读取所有音频。
- 命中凭据时新增校验读取字节为 0，不能伪造已经重读整首。
- 这项优化是减少重复读盘/网络读取；不是承诺防御能任意伪造文件身份与时间的攻击者，也没有提供跨所有硬盘/NAS 的固定倍数提速结论。

**Windows 当前缺口：** `media_source.cpp` 的可靠身份实现只有 `Q_OS_UNIX`。非 Unix 分支明确执行完整内容哈希、不签发可复用凭据。因此 Windows 必须补齐稳定文件身份、时间和打开句柄/路径一致性验证，才能达到相同性能目标；不能仅保留 QFileInfo 的 size/mtime 就宣称等价。

### 5.2 全库自动处理和协调器

`SourceRepairHandler` 接到波形队列及并行工作槽；`SourceRepairCoordinator` 负责会话、按项去重及串行访问会话。

- 对 `source_unavailable` / `compatible_unavailable`，在最终失败计数和游标推进前尝试自动处理。
- 每个 job 的自动处理次数受限，避免“修复 → 失败 → 修复”无限循环。
- 成功后刷新映射并重试**同一原件身份**，不新增一首重复音乐。
- 无可用会话时保留任务状态，集中提示连接；登录后恢复相应模式。
- 暂停、取消、切换库/模式、退出时，迟到异步回调不能覆盖新状态或自动恢复已暂停队列。
- Mac 用 QStorageInfo 判断实际文件系统类型；`/Volumes` 下也可能是本地移动硬盘，不能一概弹 NAS 登录。
- 自动处理并不等于同时对 NAS 无限并发建链接；波形工作槽与修复会话有不同并发控制。

### 5.3 去掉“连续 8 项失败即暂停”

单文件访问失败、解码失败等进入异常记录后继续后面的文件。磁盘满 `storage_full` 必须停止继续写；修复会话不可用等由协调流程暂停/重连。不能把“永不暂停”当作这项需求。

断网表现可能被底层报告成普通路径失败，也可能形成会话级错误。Windows 必须实际验证这些分支，不能声称所有网络故障都会被可靠自动识别。

### 5.4 恢复游标、计数和缓存复用

- 支持先重试既有失败，再通过 `resumeAllAfterRetry` 回到原全库游标。
- 修复“重试结束查询正在返回时用户暂停，随后又自动续跑”的竞争条件。
- `reconcilingCachedPrefix` 根据已有有效视图核对已处理前缀，避免续跑后缓存数与界面不一致。
- “当前去重待处理异常”“本轮/批次累计失败”“参考波形”“已缓存”分别表达，不得把失败计数当作坏文件总数。
- 进度以实际缓存成功数为依据，不通过把失败也加到成功数中显示全部完成。
- 任务到达 complete 仅代表扫描/处理范围结束。验收仍须按当前 track 的 waveKey 和有效视图检查准确、参考、缺失数量，不能数 peaks 文件个数。

### 5.5 播放、拖出和波形统一来源验证

- 播放 worker、波形 worker 均传递原索引 size/mtime、兼容来源、预期 SHA、凭据缓存位置。
- 验证必须在缓存快速复用路径之前，包含 publish_existing；解码后还核对来源稳定性。
- 拖出先按 libraryId + relativePath 重新查询当前索引，防止界面旧快照指向已变化文件。
- 完整拖出校验放后台，提供可取消进度；取消后不继续逐个校验剩余选择。
- 任何一项核验失败，不把未经确认的 URL 当成已成功的拖出结果。
- 原有“整首文件拖到达芬奇再剪辑”的使用方式保留；没有改成先切片导出。

## 6. 0.12.7 的界面要求

### 6.1 右键在文件管理器中打开并选中原文件

用户要求的是 **打开所在文件夹并选中这一首音频**，不是只打开文件夹，也不是仅在软件左侧定位。

- 主列表和最近试听入口均接入。
- Mac 文案“在 Finder 中显示”；Windows 使用自然的平台文案，例如“在资源管理器中显示”。
- 先按当前 libraryId + relativePath 获取原件，异步检查路径，然后调用系统文件管理器。
- 不经过 shell 拼接；特殊字符必须作为路径处理。
- 原件不可访问/不存在时明确提示，不改为选中波形、下载缓存或硬链接。
- 保留原来“在左侧定位文件夹”，两项不是互相替代。
- 当前代码已有 `explorer.exe /select,` 分支，但没有 Windows 实机验收。Windows 端需验证参数和选中行为，必要时使用可靠的系统接口实现。

### 6.2 完整移除“本剧候选”功能

- 删除右键“加入本剧候选”、候选选择器、候选创建/重命名/删除/加入/移除等 UI 入口。
- 不只是改名字或隐藏一个默认列表，也不另起一个候选名继续提供。
- 保留“个人工作区”中的“最近试听”和“常用目录”。
- 持久化模式值 1/2 保持原语义；旧模式 0 转为最近试听。不能直接拿下拉框新下标当旧设置值。
- 停止打开数据库时自动创建默认候选，停止删除最后一个候选后又自动重建。
- 历史候选表、记录和部分后端 API 保留，用于回滚和数据兼容；“删除功能”不意味着擅自删除用户旧记录。

## 9. 已做过的真实验收、尚未解决的问题

### 9.1 Mac 0.12.2 解码对照

两首雄狮少年 2 音频与 Windows 提供的原件 SHA 一致。修复后分别解出约 285.893167 秒、37.049292 秒，错误数 113、3，读到 EOF，保存波形并保留 approximate/reference。GUI 能显示波形及推进定位播放。**未完整听审。**

### 9.2 2026-10-29 / 0.12.6 两库夜间结果

| 项目 | 当时实测 |
|---|---:|
| 索引曲目 / 素材库 | 35,723 / 2 |

统计来自独立 reader 使用真实 Index、waveKey、loadWaveView 对只读索引快照核验，不是 peaks 文件数量。“累计失败 2170”不是 2170 首坏音乐。

五条剩余原因：

- 20299：可读但为 0 字节 WAV。
- 30893、30933、31101：相同的 1005 字节 MP3，只有 ID3 与 MPEG Info 帧，声明音频帧数为 0，没有可恢复的音频负载。
- 35624：原目录及规范化名称检查后仍没有索引 MP3；没有擅自用另一处同名 FLAC 替换。

这些需要找回/重新导出原件或由用户明确选择来源，路径修复不能创造缺失音频。

定点 21379 的两个规范化同名候选，通过唯一匹配已索引 size/mtime 选出正确版本，生成准确波形。24057 原索引 size/mtime 为 0，原件现已可读；核对完整哈希和路径后，仅更新该条版本元数据并生成准确波形，ID/路径/收藏标签保留。

**24057 的刷新是一次性维护操作，不是已经交付的“自动更新所有过时索引”功能。** Windows 不应把它误写成批量自动迁移需求，更不能按“文件看起来同名”随意更新记录。

## 10. Windows 开发与验收顺序

### 第一步：基线与数据保护

检查本机源码版本、Git 未提交修改、当前 APP、真实 profile、波形目录和构建工具。备份资料与可用安装包，保存索引身份、库配置、收藏标签摘要。建立独立开发分支及数据目录。

先读本说明和包内完整文件清单，再读源码中设计、验收文档。不要先覆盖 Windows 当前工作树。

### 第二步：先移植通用逻辑和 UI

合并错误分类、compatible_sources、队列处理、暂停恢复、缓存计数、候选下线、原件定位与统一来源消费。保证原有 Windows 解码、拖出、搜索、收藏、标签、共享缓存和主题回归。

### 第三步：补齐 Windows 专属实现

实现网络盘识别、会话和路径映射、硬链接能力检测、异常缓存兜底、稳定文件身份及校验凭据，替换非 Apple 占位入口。按真实环境验证权限与连接，不能写死 Mac 盘路径或账号。

### 第四步：定点验证，再扩大范围

| 测试组 | 必须检查 |
|---|---|
| 旧资料 | 不改 ID/相对路径/收藏/标签；旧波形可读；候选旧记录保留；旧模式 0 回落最近试听 |
| 文件管理器 | 主列表/最近试听均打开并选中原件；空格、中日韩文、引号、#、%、&；长路径/UNC；原件缺失不转到兼容文件 |
| 原件正常 | 不创建多余链接/副本，不多一次无意义的完整校验 |
| 路径异常 | 单文件/批量入口/全库入口一致；只处理适用类型；原件内容和路径不改 |
| 消歧 | 唯一稳定版本可选；多个匹配、未知属性、候选变化和中间目录歧义拒绝 |
| 硬链接 | 同源身份和内容校验；不支持/拒绝/跨文件系统可安全兜底；已有目标不覆盖 |
| 校验 | 首次完整 SHA；未变复用并报告 0 新增校验字节；重启复用；替换、同大小改写、预期 SHA 变化重新校验 |
| 凭据异常 | DB 缺失/损坏/不可写、身份不可靠退回完整校验，不绕过 |
| 并发 | 同文件去重、不同文件正常并发；4 波形槽接入修复后不死锁、不重复生成、不泄漏会话 |
| 暂停恢复 | 修复过程中暂停；重试最后一项返回时暂停；切库/模式、退出/重启；迟到结果不能自动恢复旧任务 |
| 错误继续 | 连续超过 8 项单文件失败仍处理后项；磁盘满安全暂停；网络/会话错误有可解释恢复 |
| 内容异常 | 0 字节、只有标签无音频、缺文件、可恢复解码错误；保留已有参考/部分采样和诊断 |
| 拖出播放 | 经验证的来源才使用；拖出可取消；变化后不复用旧快照；不把兼容来源当原件显示 |
| 正式库验收 | 单独核对有效准确/参考/缺失与去重异常；不只看 complete、不数缓存文件当曲目 |
| 包装安装 | 干净 Windows 用户环境可运行；依赖齐全；版本一致；升级和回滚资料保持 |
