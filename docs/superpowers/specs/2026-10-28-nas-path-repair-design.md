# NAS 路径兼容处理 0.12.3

用户要求把已验证的兼容副本流程放进“异常与重试”，停止独立批量建库。原始音频永不修改；路径失败逐项记录并继续，不再因连续八次失败暂停。

## 范围与交互

- 波形记录增加“批量处理路径问题”，只读取当前素材库中去重的 source_unavailable 异常。解码、空间和超时异常不混入。
- 当前支持已验证的绿联 UGOS Pro NAS。原生 Qt 网络客户端，运行时输入地址、账号、密码；不把账号密码或令牌写入配置、日志、源码或检查点。
- 选择素材库、SMB 挂载根目录、NAS 端共享根目录和独立副本目录。检查副本目录与全部原素材库不重叠。显示待处理数，开始前说明只创建副本及占用空间。
- 后台逐项匹配 NAS 实际名称，逐层用 NFC 比较但拒绝多义匹配。原件属性核对；NAS API 仅列目录和下载；通过 SMB 新建副本，不使用服务端移动或改名 API，不覆盖已有文件。副本使用独立管理目录和规范名称，校验原件 HTTP 下载与 SMB 副本的完整 SHA-256。
- 显示逐项结果和进度，暂停在当前项安全完成后生效；检查点支持继续，重启后重新登录。失败项保留证据，其他项继续。
- 已验证副本建立版本绑定映射，沿用原曲 ID、标签、收藏和原文件路径。波形、播放和拖出使用兼容副本，并显示副本提示。原文件复制/定位和删除仍明确指向原件。
- 映射建立不等于波形成功。完成后定点重试，只有波形成功才按原流程消除待处理异常；参考波形始终保留参考标记。

## 方案

独立脚本由用户取消；直接改原文件名违反原件保护要求；采用原生客户端加兼容映射。映射使用额外表，保留索引 user_version=6，使旧版回退仍可打开原资料。现有 194 份副本保留，不继续独立任务，也不自动加入素材库。

## 验收

真实 NAS 定点修复至少一首已失败音频，原件路径、大小、mtime 不变，副本 SHA 相同；最终 APP 内入口、进度、暂停/续跑、波形和播放验证。自动化覆盖同名规范化冲突、版本变化、缺失/被改副本、检查点和连续超过八次失败。完整 CTest、最终 APP Cocoa 插件加载与原生回归分别报告。macOS 27 Apple 芯片构建，保留 Qt 6.11.2 官方修复及部署校验；仅临时签名，公证状态如实说明。
