# 源音效管理工具 · 0.12.2

面向公司共享音乐库的搜索、行内波形试听和整首原文件拖放。本版采用「清透浅色 / 石墨深色」界面，统一顶栏、目录、列表与全宽紧凑播放条。保留多个素材库、完整曲目列表、共享波形、后台让路及个人工作区。

## 0.12.2 解码修复

- 不再因整个文件累计超过 32 次可恢复解码错误而丢弃有效波形；仍对无进展的解析循环设置退出限制。
- 保留可用采样，分别记录解码到结尾、提前中断、尚未取得有效音频、路径访问失败。界面不再把所有解码异常称作“损坏音频”。
- 可用音频的异常提示、实际解码长度和声明时长保存在本机波形中，重启后可查看。异常波形仍标记为参考，不自动升级为经过完整验证的共享波形。
- 兼容已有缓存，不清空、不自动重建全库。仅对指定样本验证；原有 1 / 10 MiB/s、不限速及 1 / 2 / 4 首并行保持。
- Mac 构建与定点回归见 [给同事 AI 的说明](docs/macos-decoder-handoff-0.12.2.md)。Windows NAS 实测不代表同一 Mac 挂载环境已验证。

## 0.12.1 改进（保留）

- “设置 → 性能”增加“超快 · 不限速”，取消后台解码的音频读取限速；原有 1 / 10 MiB/s 档位保留。实际速度仍受网络、磁盘、解码能力影响。
- 全库波形准备可选同时处理 1、2、4 首，使用独立的解码工作进程利用多核。默认保留 1 首，单首解码仍为一个线程。失败与参考波形重试仍逐首进行，支持不限速。
- 有限速时额度按并行上限固定分配，不按每首分别给满额；少于设定数量的任务运行时可能用不满总额度。保留试听、收录及系统繁忙让路，切换速度/并行数会重新准备尚未完成的任务。
- 并行结果按索引顺序登记进度，防止先完成后面的文件导致断点续跑漏项。最多保留四个正在处理或等待登记的任务，已有波形继续复用。进度页显示当前档位和处理数量；暂停或完成时释放额外解码进程。

0.12.1 的 Mac 版本需要使用 [超快并行版构建说明](docs/macos-performance-handoff-0.12.1.md) 及专用完整构建包；保留此前 Qt Cocoa 闪退修复。0.12.0 的实机结果不等于 0.12.1 已完成 Mac 验收。

## 这版的使用方式

- **多个素材库**：重复使用“添加音乐目录…”可连接多个本地或 NAS 音乐目录；左侧目录树和“设置 → 素材库”分别列出每个库。刷新、共享波形设置和移除操作都针对明确选择的素材库。
- **从列表移除与恢复**：在素材库、左侧文件夹或音乐行的操作菜单选择“仅从列表移除”，本机索引会立即更新，原音乐和共享缓存保持原位；刷新扫描也不会让排除的文件夹或单曲自动回来。误排除可在“设置 → 素材库”撤销排除，然后重新扫描。移除整个库后重新添加即可恢复收录。
- **处理原件**：另有明确确认的“移入系统回收站并从列表移除”操作。软件先核对源路径属于该库，不允许牵连其他已连接音乐库或共享缓存；回收站不可用时保持原件与索引不变，不会回退为永久删除。对 NAS 原件的移动会影响所有共享用户，应先确认选择正确。
- **外观与名称**：软件显示为“源音效管理工具”。在“设置 → 显示 → 外观模式”选择跟随系统、浅色或深色，切换即时生效并记住选择；主题覆盖主界面、设置、列表和波形。切换外观不重建音乐索引或重复读取原音频。
- **安装与升级**：Windows 安装版按当前用户安装并创建快捷方式，无需管理员权限。免安装版解压到本机磁盘运行。两版使用同一程序；安装或卸载不会清除已有索引、收藏、设置及波形缓存。
- **参考波形标记与时长**：参考波形采用和普通音乐相同的中性波形，只在起点显示小标志。悬停可见“位置仅供参考”。参考条目试听后，列表显示播放器从原文件得到的时长；此前从参考波形推算时显示“约”，避免误以为准确。
- **恢复参考波形**：打开“设置 → 波形缓存 → 重新分析参考波形”。仅重做已登记的参考条目，正常完整波形不参与。可暂停、继续，使用“性能”页当前速度和剪辑优先设置。新结果保存前仍显示旧图；复核通过的改为完整波形并尝试同步共享缓存，仍有异常的保留提示。关闭软件会保留进度，下次从此入口继续。
- **完整列表**：进入目录或搜索后，一次展示当前范围的全部曲目和准确数量，可直接滚动到末尾。音乐列表不再需要“加载更多”，也没有 2,000 首显示上限。后台只查询本机曲目信息，波形仍按可见行准备。
- **设置入口**：右上角“设置”或 `Ctrl+,` 打开独立窗口，分为播放与浏览、波形缓存、性能、显示、素材库、快捷键。设置即时应用，关闭窗口不停止试听或缓存准备。底部缓存进度可直接打开波形页，异常不会强行弹出设置。
- **共享波形**：在“设置 → 波形缓存 → 设置共享缓存目录”选择已收录的素材库与专用共享文件夹。已有库身份、索引、收藏、标签保持。缓存可以放在音乐根目录的子目录，扫描会在进入前跳过它。当前用户指定位置为 `Z:\剪辑音乐\音频缓存`；其他电脑应选择其挂载路径下的同一个文件夹。
- **补齐缓存**：在“设置 → 波形缓存”点“检查更新后的素材库”或“准备全部波形”。已有完整本机波形可补充到共享显示缓存，不重新读取音乐内容；参考波形不作为完整波形发布。首次没有缓存的音乐仍需要分析。进度可暂停和继续。
- **后台让路**：在“设置 → 性能”调整。默认开启“剪辑优先”，后台读取为 1 MiB/s，可选 10 MiB/s。试听与目录收录期间，后台波形等待；持续 CPU 繁忙时自动让路，空闲后继续。点击曲目和本机已缓存波形仍优先。暂停播放后不再持续发送播放位置回调。
- **异常恢复**：在“设置 → 波形缓存 → 异常详情与重试”按原因筛选、分页查看，可试听原文件、定位文件夹、复制路径，或“只重试失败”。参考波形单独查看。旧版没有保存的失败明细会明确列为历史缺失，不能凭数量推断具体文件。
- **紧凑目录**：文件夹默认每级缩进 12 个逻辑像素，在“设置 → 显示”可选 8 / 12 / 16；音乐行距可选紧凑、标准、宽松。长名称悬停可看完整路径，目录栏仍可拖动调整宽度。
- **个人工作区**：左栏点击“个人工作区”展开。可建立、命名多份候选清单，查看最近 100 首真正试听过的音乐，或常用文件夹。音乐行右键加入当前候选；目录右键加入常用目录。双击候选/最近条目试听，双击常用目录定位到目录树。
- **查找与试听**：顶部搜索音乐名称与路径；左侧搜索文件夹名称，并定位真实目录。匹配文字按当前外观高亮。悬停波形显示位置时间；单击从该处试听，按住拖动则交给达芬奇整首原文件。

个人工作区默认收起，底部保持紧凑播放条。所有清单和最近记录只保存引用，不复制、移动或修改音乐；从列表或工作区拖出的仍是服务器原文件 URL。

## 缓存与性能边界

本机 SQLite 索引供搜索，网络目录扫描与音频分析在后台。当前范围完整曲目信息会进入内存，名称、路径和标签越多，占用也会增加；并不同时读取全部音乐或波形。列表仅绘制和准备可见行；峰值数据按约 64 MiB 和 512 项双重预算淘汰，另有 16 MiB 绘制缓存。这些是局部缓存预算，不是整个进程的内存上限。

播放位置、波形和个人标记更新通过素材 ID 定位对应行，避免每次遍历完整列表。旧查询在开始前及每 128 行读取时检查是否失效；正在执行的 SQLite 语句/排序不会被即时中断，完成后丢弃过期结果。整段工作位于后台，不阻塞界面。当前音乐结果使用同一个索引快照，避免分页追加时混入不同版本。

完整指纹缓存与共享显示缓存是两个层次。共享显示缓存以共享库身份、相对路径、文件大小和修改时间匹配，并校验缓存内容；它不会冒充完整原文件指纹。若人工替换原文件同时保留大小与时间，旧波形可能暂时仍被显示。刷新素材库并发现文件大小或修改时间变化后，会拒绝旧版本缓存。

同一素材的正常共享生成通过进度租约减少重复分析；等待显示状态，可取消。客户端中断或共享连接异常时等待有期限，之后可在本机继续；异常恢复时仍可能重复分析。协调不依赖不同电脑的系统时钟或进程号，也没有中央常驻服务。

后台限速作用于单台客户端的解码读取，每个工作进程含 256 KiB 初始余量；试听、指纹检查及缓存读写不计入该音频读取额度。不限速不会限制音频读取速率；开启剪辑优先时仍会在持续繁忙或试听期间让路。目录扫描默认限速约 400 项/秒。系统繁忙判断使用 CPU 负载和延迟恢复，不检测达芬奇 GPU 渲染，不是全公司统一带宽或 CPU 硬上限。

首次准备 1 TB 音乐仍有实际读取成本；缓存能减少后续重复工作，不能消除 NAS 不在线、网络延迟、损坏音频或不支持的编码。已缓存的参考波形属于缓存总数的子集，并不表示精确完整分析通过。旧版参考明细需重新检查本机缓存后收录。

## 本机资料与升级

虽然对外名称已更新，内部资料目录仍使用 `%LOCALAPPDATA%/AudioLibrary/AudioLibrary/row-wave-v0.4/`，本机波形沿用上一级 `peaks/`，因此旧版资料保持可用。升级早期版本 3 索引前，自动保存通过校验的 `library.pre-0.8.sqlite` 备份；已有有效备份不覆盖，无法安全备份则停止升级。

`workspace.sqlite` 保存个人清单、最近试听和常用目录；`waveform-failures.sqlite` 保存异常与参考条目；`browser.ini` 与 `workspace-ui.ini` 保存界面偏好。数据库保存在本机，不放到 NAS 供多人同时打开。同一数据目录只允许一个界面实例。退出后备份整个资料目录，可保留个人配置。

`performance-last-session.json` 仅保留最近 256 个操作种类及耗时，不记录搜索词、不上传。开发测试使用隔离目录，不混入正式数据。

## 已知未验收项

公司 NAS 上 6–10 人同时工作、1 TB 全库吞吐、达芬奇 20/21 工程内软件直拖，仍需对应环境实测。0.12.0 已在 M4 Pro / macOS 27.0.1 上完成构建和针对性 Qt 闪退修复：应用自动测试 27/27、最终插件原生测试 12/12、针对性重复 30 次通过，可供内部试用。Mac 上单曲/文件夹移除与恢复的界面流程仍未完整验收，见 [Mac 修复复测核验](docs/mac-fix-validation-0.12.0.md)。自动测试与本机多进程验证不能代替这些验收，也不足以证明全面超过出片。

没有情绪自动识别、BPM/调性分析、共享个人标签、音频预取副本或片段导出。目录仍为手动刷新，不自动删除失联条目或原件。磁盘旧缓存尚无自动容量清理界面。Windows 包未做发行签名；Mac 0.12.0 修复版仍只有 ad hoc 签名，尚无 Developer ID 签名和公证。

## 开发与验证

C++20、Qt 6.9.3、FFmpeg 7.1.1、CMake、MinGW 13.1。构建入口 `scripts/build.ps1 -Package`；此工作目录可通过 `-ToolchainRoot E:\AI\audio-library` 复用工具。构建脚本先运行完整回归，通过后从同一干净部署目录生成安装包和免安装 ZIP。打包条件见 [Windows 发布说明](scripts/README-packaging.md)。

本轮结果见 [0.12.2 验证记录](docs/validation-0.12.2.md)。历史记录保留于 docs，不代替本轮验证。

Mac 修复版使用 [已回传验证的构建流程](packaging/macos-0.12.0-verified-recipe/README.md)，在 Qt 部署后装入修复的 Cocoa 插件，再签名和验证。旧 `scripts/prepare-macos.sh`、通用 `build-macos.sh` 及 GitHub 构建流程尚未自动接入本次插件修复，单独运行不能作为修复版交付。详见 [macOS 27 构建与使用说明](docs/macos-release.md)。当前 Windows 电脑无法执行 Mac 原生构建、签名或达芬奇拖放验收。
