# 0.6.0 波形整首拖出与浅色工作台

日期：2026-09-24。Windows 预览版，延续原文件工作流和已有索引、缓存、收藏与个人标签。

## 本次变化

- 单击波形继续定位试听；按住并移动超过系统拖拽距离，直接拖出这一行的整首原音乐。与名称拖拽共用原文件 URL，只有 Copy 操作，不移动原件、不生成片段。
- 波形拖动不改变选曲，不会触发“选中后试听”；取消或松开拖动不补发点击。拖动时显示轻量文件名预览，中文与共享路径保留。
- 浅灰侧栏、白色列表、蓝色选中与播放进度，统一系统字体、间距和细分隔。底部 58 px 播放条保留音量、收藏和标签，行高 52 px。
- 当前目录标题只显示末级名称，悬停查看完整路径与搜索范围。每行仍显示所在目录，左侧定位逻辑保留。
- 右上角“波形缓存”展开准备操作与详情。收起不暂停，入口显示准备数量或异常数量；遇到阻止继续的错误自动展开。

## 行为验证

先增加拖拽回归测试：旧实现无法从波形产生文件拖拽，出现预期失败；实现后通过。覆盖以下场景：

1. 在另一行波形拖动时，URL 属于按下那行，包含中文目录和共享根路径；不发出试听或切换选择信号。
2. 完成或取消拖动后继续移动、松开都不误触试听；下一次单击仍能定位。
3. 小于拖动阈值的移动仍为单击；拖动过程中模型刷新则取消旧手势。
4. 缓存面板展开、收起不停止准备；连续不可访问导致暂停时自动展开错误详情。

最终八组 CTest 全部通过，共 74.46 秒；窗口组 42.73 秒。回归涵盖索引、目录定位、窗口恢复、最小窗口波形点击、播放进程、读取预算、解码异常、并发缓存和大封面读取进度。运行记录保存在开发目录的 `test-output-0.6-final-tests.txt`。便携包另运行静音播放定位检查，通过。窗口手势测试共 37 个场景（含队列与恢复），拖拽用例先红后绿。

原生窗口检查覆盖 1320 × 850 和 980 × 640 客户区；窄窗口内波形、时长与底部控件仍可见。实际从波形拉出时显示正确文件名，取消后没有误播放；尚未把这项观察作为外部程序已接收文件的证据。

拖拽对象采用父对象管理的堆分配，遵循 [Qt QDrag 文档](https://doc.qt.io/qt-6/qdrag.html) 的生命周期要求。

## 现场升级

从桌面快捷方式启动 0.6.0 后，保留原来的“爱看音乐 / 音乐 / 6.韩国影视”范围，显示已有波形。缓存面板仍显示 59,429 / 59,443、参考波形 7,072、失败 14，与退出旧版前一致。没有重新开始整库生成，也没有修改 NAS 原件。

开发应用启动的程序可能继承 Windows 打包应用的数据目录重定向，因此现场验收使用系统桌面入口。此时可见的原有工作数据与开发工具中的重定向副本不同；本次未合并或覆盖两份数据。

## 性能与边界

继续使用 Qt 原生列表和可见行波形绘制，没有增加网页容器、模糊特效、常驻动画或后台扫描。文件预览仅在拖动时绘制一张小图；缓存预算、波形队列与读取限速保持原实现。本次未做新的 6–10 人 NAS 并发吞吐测试，不用界面观感代替性能数据。

自动测试确认原文件 URL 和交互逻辑；尚未在 Resolve 工程中完成这版波形外拖验收。Mac 构建与原生拖拽仍需 Apple Silicon 实机验证。原来的 14 条异常不因界面升级自动修复，仍可查看详情并重试。
