# 0.5 波形直读与全库准备

用户授权：修复波形排队/卡顿，并缓存全部波形；不更改音乐原件。

已确认：可见 FLAC 约 84 MB；旧队列仅一个工作进程且每秒 1 MiB，未知时长的部分波形被隐藏；本机缓存命中仍需 NAS 文件属性与指纹，缓存读取也逐首排队。波形完成时还在界面线程写入本机索引，可能等待数据库锁。

实现与验证：
1. 用离线重开测试复现缓存仍依赖原文件。新增按素材版本存储、带校验的本机直读轮廓；独立后台批量读取可见缓存，不被慢解码阻塞。刷新要求重新核验，过期缓存显示状态。
2. 复用生成工作进程；提供解码时长/进度，未知时长时不伪造整首轮廓。把时长写入移出界面线程；单任务超时后继续队列。
3. 全库准备使用本机索引按 ID 分页，单个解码任务、可暂停续跑、进度持久化、失败计数与重试。先处理可见/选中曲目，缓存用磁盘，内存有界；默认预生成 10 MiB/s，可选 1 MiB/s。
4. 已完成波形可无网络读取；对源变化、损坏缓存、重启、取消、失败、前景抢占加入回归。全套测试和当前实际目录验证后打包 0.5，启动用户授权的全库准备，准确报告已完成量而非声称瞬间完成 1 TB。

边界：本次实现当前电脑的全库准备与既有共享缓存发布，不承诺实现整份远期方案的共享租约、近期音频缓存或公司多人资源协调。保留现有索引配置以继承用户最新浏览、收藏与收录，关闭当前 0.4 后切换 0.5；索引 schema 仍为 3。

实施结果：上述四项已完成。真实目录 10 首 FLAC 波形已生成；全库任务可暂停续跑。真实 MP3 库中有可解码但含异常数据的文件，因此加入独立“参考波形”缓存标记及计数，保留可读轮廓但不作为共享完整波形或可靠时长。补充了大封面进度、实际速率切换和提前显示总数。验证与尚未完成的整库/多人验收见 `validation-0.5.md`。
