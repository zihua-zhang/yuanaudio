# 开发预览 0.2 验证记录

日期：2026-09-20。环境：当前 Windows 11 工作站，Ryzen 5 9600X / 32 GB；Qt 6.9.3、FFmpeg 7.1.1、MinGW 13.1。保留 0.1 软件和原本用户数据，使用 SQLite 备份及独立测试目录。没有全库重扫，没有改写或上传音乐，没有往公司 NAS 写入测试缓存。

## 实际发现与修复

1. **封面 MP3 波形失败**：旧版对无封面的自制两秒 MP3 正常；加入 32 × 32 JPEG 封面后，解码结束却没有采样。新增固定合成夹具复现，改为直接选择 FFmpeg 音频轨道解码，校验完整时长与非零峰值。
2. **封面 MP3 试听停在开头**：播放压力测试又复现 `playing=true` 而进度始终为零。Qt 6.8.3 解复用器会用非音频数据包判断音频结束；升级至包含相关轨道过滤的 Qt 6.9.3 后，正常播放及 300 次切歌均通过。组件源码未做私有二进制修改。
3. **离线恢复**：旧版对不存在文件加载失败后，即使文件重新出现，点击播放仍不恢复。新版收到媒体错误后会重新加载原文件；当前行点击/播放同时可以重试失败波形。错误原因不会被一般退出文字覆盖。
4. **缓存并发初始化**：旧版十个进程同时初始化时，200 次中出现 4 次误报空目录/无效配置。完成配置独占发布、等待者读取已发布结果后通过。另注入远程客户端留下的七天旧锁和半写入临时文件，验证可以恢复。活动初始化等待最多五秒；远程遗留锁超过一分钟可接管，独占重命名保证不覆盖已经发布的库 ID。
5. **损坏文件误缓存**：MP3 非法尾部、WAV 长度头与实际文件不符、解码器报告损坏数据时，新版只显示可读取部分并提示“仅供参考”，不保存为正常缓存、不把不完整时长写入索引。大量错误或无法识别的文件明确失败。

从当前本机数据库做一致性备份：59,443 首，记录的音频容量合计 762,181,673,400 字节。选择 26 个查询，覆盖常用中文情绪词、单字、文件夹名称、完整音乐名称、无结果及空查询；每个查询运行 20 次，总计 520 次。

- 中位数：1.999 ms。
- P95：4.476 ms；最大：46.124 ms。
- 含每次打开本机数据库连接和查询时间；不含界面 120 ms 防抖、列表绘制与网络音频读取。
- 操作系统磁盘缓存可能已热；这是本机真实索引结果，不是 NAS 在线遍历耗时。

## 三首 NAS 小样本

顺序读取三首约 3.9–5.2 MB 的 MP3，只读原件、本机写测试波形。共享缓存参数为空。下表是进程启动到退出的墙钟时间；音频文件和系统网络缓存可能已热。

| 样本 | 未命中波形缓存 | 再次读取 | 结论 |
|---|---:|---:|---|
| 带封面 MP3，5,165,182 字节 | 162.3 ms | 27.1 ms | 生成成功；第二次使用本机缓存 |
| 普通 MP3，3,923,843 字节 | 204.7 ms | 27.8 ms | 生成成功；第二次使用本机缓存 |
| 带封面且含损坏数据的 MP3，4,639,123 字节 | 154.9 ms | 135.1 ms | 显示参考波形与警告；两次均不保存损坏缓存 |

针对第二首再做五组交替版本对照，每次使用全新的波形缓存目录：0.1 中位数 **2,005.6 ms**，0.2 中位数 **190.5 ms**。这是一个小文件在当前机器和网络、文件缓存可能已热条件下的对照，不能外推成整个 1 TB 素材库的提速倍数。

原始测量和含内部路径的输入仅保存在被 Git 忽略的本机 `test-output/` 中，本报告不披露服务器地址或音乐名称。

## 复现入口与组件依据

- `scripts/build.ps1 -Package`：五组必过测试及 Windows 打包。
- `tests/codec_smoke.py <exe>`：开发环境需 imageio-ffmpeg，仅生成测试素材，不随软件发布。
- `tests/player_stress.py <exe>`：300 次切歌。
- `real_index_benchmark <SQLite备份路径>`：真实索引测量，不应直接传入生产数据库。
- [Qt 6.8.3 解复用器](https://github.com/qt/qtmultimedia/blob/v6.8.3/src/plugins/multimedia/ffmpeg/playbackengine/qffmpegdemuxer.cpp) 与 [Qt 6.9.3 解复用器](https://github.com/qt/qtmultimedia/blob/v6.9.3/src/plugins/multimedia/ffmpeg/playbackengine/qffmpegdemuxer.cpp)：后者只对相关轨道做结束位置判断。
- [FFmpeg 官方解复用/解码示例](https://ffmpeg.org/doxygen/7.1/demux_decode_8c-example.html)：音频轨道选择及 send/receive 接口依据。
