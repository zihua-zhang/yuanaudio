## 构建

使用全新解压目录，不要覆盖上次成功的 0.12.0 工程或安装镜像。目录包含完整 `application/`、`qt-cocoa-project/` 和 `handoff/`，不要重新拼接旧包。`source-sha256.json` 可校验每个来源文件。

在 macOS 27、Apple Silicon、Xcode 27 命令行工具环境中，从解压后的顶层目录执行：

```bash
bash 开始构建.command
```

脚本准备精确 Qt 6.11.2 和工具，下载并校验完整 Qt 源码，应用官方 `8148c48` 修复，重建 Cocoa 插件及原生回归，然后构建 0.12.1、运行全部应用测试、部署修复插件、签名与生成 DMG。FFmpeg 沿用 7.1.3。已有 Mac 测试过的四个修复脚本原样随包提供；启动入口的串联在 Windows 做静态检查，仍需本机执行验证。

如果复用上次下载的 Qt SDK，只能复用精确 6.11.2 的 SDK 和已校验下载归档；不要复制旧的 CMake 构建目录，不要将回传的三份 Qt 源文件当成完整源码。可按 `application/scripts/rebuild-qt-cocoa-fix.sh` 和 `build-macos-fixed.sh` 的入口传入现有 SDK，仍保留本包父目录布局。

不要运行旧 `prepare-macos.sh` 或绕过 `YUANAUDIO_COCOA_PLUGIN` / 哈希门禁生成分发包。不要通过禁用无障碍访问规避原生回归。原生 GUI 测试与产品 GUI 自动化串行执行。

## 本次重点验证

1. “设置 → 性能”保留 1 / 10 MiB/s，新增“超快 · 不限速”；“同时准备”支持 1 / 2 / 4 首，默认仍为 1。选择后重启，设置应保留。
2. 全库准备开启 4 首 + 不限速，用独立测试文件观察多个解码工作进程同时活动；单首解码线程数仍为 1。总并行上限包含当前列表后台任务，不应额外启动第五个解码任务。
3. 1 / 10 MiB/s 为单客户端总后台额度，分配给各任务；0 表示不限速，不得被恢复逻辑夹回 1 MiB/s。失败重试、参考波形重试仍为单首，但必须支持不限速。
4. 暂停、试听让路、切换并行数/速度、跳过当前、刷新素材库、退出再续跑：已完成波形保留，未完成文件不能因后面的文件先完成而漏掉。修改速度会重新分析尚未完成的当前任务，已完成文件不重做。全库结束或暂停后，额外并行解码进程应释放，日常浏览不持续保留四份解码运行时。
5. 复核之前的文件搜索、浅色/深色、波形点击、波形整首拖放流程。公司 NAS 与达芬奇实际拖放没有条件时，明确标为未测。
6. 对同一组冷缓存测试文件分别用 1 首不限速 / 4 首不限速测总耗时，并记录 CPU、内存、读取量及测试位置（本机盘还是 NAS）。每组用独立缓存目录，不能让第二组命中第一组缓存。速度提升不作固定倍数要求；数据用于判断网络或解码瓶颈。
