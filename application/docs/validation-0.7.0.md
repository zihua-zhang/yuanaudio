# 0.7.0 绘制减负、搜索恢复与缓存状态

日期：2026-09-24。Windows 预览版。保留整首原文件工作流、已有索引、波形、收藏与个人标签。

## 本轮实现

- 每行波形的灰色和蓝色轮廓绘制后复用，播放更新只裁切已播放范围并画游标。绘制缓存按文件版本、尺寸、屏幕缩放、像素位置、波形进度和结构区分；波形变化时只使对应素材失效。缓存计费上限 16 MiB，超限尺寸直接绘制；此预算不代表整个软件的内存上限。
- 播放进度回调和波形更新不再对列表每一行重复计算文件版本哈希，同一秒内不重复更新播放时间文字。
- 加载更多使用增量插入，保留已有行、选中和滚动；达到 2,000 首显示上限时不再取消可见波形任务。
- 数据库打开、查询、读取和提交错误会明确显示，保留上次结果并提供重试。搜索中的旧结果有文字标识，使用既有结果栏，避免插入等待横幅导致列表上下移动。空库和无匹配结果各自提供可执行操作。
- 音乐搜索在中文输入法组词时暂缓提交，提交或取消组词后检索最终文字。当前路径直接显示，可悬停查看完整范围。
- 记住音量、选中后试听、窗口位置大小和侧栏比例；损坏的布局设置退回可用布局，数值音量限制在 0–100。
- 普通刷新保留本机波形。成功扫描或已经提交音频变化的部分扫描，保留旧准备计数与异常并标记待检查，停止旧批量队列；无变更提交的失败或取消不重置原状态。再次检查按新版索引核对有效缓存，不因超过 24 小时而全库重新解码。
- 可见缓存仍先显示再核验；手动刷新要求的核验时间写入续跑状态，重开后继续有效。参考数量明确为已缓存的子集；收起面板仍显示异常或待检查。

## 绘制性能对比

Windows、Qt 6.9.3、MinGW 13.1、Release。合成双声道波形采用格式上限 2,048 个桶、stride 4,096、48 kHz；单行逻辑尺寸 720 × 38、150% 缩放。在同一个离屏画布上交错执行两种算法，各 1,200 次变化播放头重绘，包含函数内裁切和游标。排除音频读取、解码、整个窗口、声卡和 NAS 起播延迟。

| 指标 | 0.6 原绘制算法 | 0.7 缓存命中绘制 |
| --- | ---: | ---: |
| P50 | 0.1360 ms | 0.0289 ms |
| P95 | 0.2417 ms | 0.0521 ms |
| 最大值 | 0.4297 ms | 0.2623 ms |
| 1,200 次总耗时 | 184.93 ms | 38.54 ms |

该样本重复绘制总耗时降低约 79%，约为原来的五分之一。首次生成 0.5731 ms，单项计费 502,296 字节；1 次构建后命中 1,200 次。首次生成有额外成本，不把热缓存成绩当作冷启动成绩。运行 `build/wave_renderer_benchmark.exe -platform offscreen` 可复测；记录为 `test-output-0.7-wave-raster-benchmark.json`。结果随机器和负载变化。

原生候选窗口另以 1 秒间隔采样 20 次：1320 × 850、当前范围 32 首、约 10 行可见暖缓存、无试听/全库准备。0.7 主程序工作集均值 113.06 MiB、最大 113.36 MiB，19.257 秒累计 CPU 1.469 秒（约单核 7.6%，不是整机百分比）。0.6 记录为主程序加一个空闲波形进程，合计工作集均值 128.25 MiB、最大 128.40 MiB，19.276 秒累计 CPU 2.047 秒。两次后台进程状态不同，这些短时观测不能证明整机性能提升或内存下降，也不能替代长时间连续浏览、后台准备或公司多人实测。记录：`test-output-0.7-resources-baseline.json`、`test-output-0.7-resources-candidate.json`。
