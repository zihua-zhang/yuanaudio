# 0.9.1 参考波形核验与恢复

## 已复现的原因

2026-09-25，只读查看当前异常目录：共 7,084 条记录，参考波形 7,072 条（FLAC 6,012、MP3 1,059、WAV 1），失败 12 条。样本按各格式的首、四分之一、中间、四分之三和末尾位置选取，共 11 个，不将样本比例外推成全库修复率。

5 个 FLAC 样本中，4 个在最后附有非音频数据。旧版完整解出原音频后，对尾部报一个解码错误，因而把整首标为参考。独立 FFmpeg 7.1 校验得到的完整 PCM MD5 与 STREAMINFO 内的 MD5 完全相同，采样数也完全相同；第 5 个样本少了 512 个采样，MD5 不相同，须继续标为有异常。

合成 MP3 实验证明：正常音频追加合法 APEv2 / Lyrics3v2 标签也会被旧版标为参考。大标签还会影响解码器对首尾填充采样的判断。直接忽略最后一次错误不安全：实际截断、中部破坏和未知尾数据必须继续保守处理。

此外，旧版“只重试失败”排除了参考记录，“重新检查全部”则直接复用已有参考波形；仅改解码器还不够，必须增加有范围的重分析入口。

## 修复原则

- FLAC 按格式规范逐帧核验有效位深的小端、有符号、交错 PCM。只有已知完整采样数与非零 MD5 均完全吻合，才能将出现解码警告的结果升级为完整波形。采样缺失、校验失败或证据不足继续保留参考；无有效 MD5 时严格检查帧 CRC。
- MP3 只在确认 MPEG Layer III 文件头后，将严格验证的尾部标签排除在解码读取范围外；还须确认尾部标签恰好接在完整 MPEG 帧之后，避免将音频中的相似字节当成标签。不修改原件，不随意裁掉未知数据。标签检查最多读取 1 MiB、最多 8 层，读取仍计入后台预算。
- 设置增加“重新分析参考波形”，沿用单任务、暂停续接、后台限速和剪辑优先。已有完整显示在重分析期间保留；失败后保留可用旧图。
- 成功核验后保存准确缓存并同步共享目录。仍异常的记录继续可见，不把“处理过”表述成“修好了”。

依据：[FLAC 官方完整性说明](https://xiph.org/flac/features.html)、[FLAC 格式规范 RFC 9639](https://www.rfc-editor.org/rfc/rfc9639.html)、[TagLib 保存的 APEv2 原始规范](https://raw.githubusercontent.com/taglib/taglib/master/taglib/ape/ape-tag-format.txt)，以及随现有开发环境保存的 FFmpeg 7.1.1 官方源码。校验只用于确认本地音频内容一致性，不用于安全认证。
