# 当前需求与 0.7 验收范围

日期：2026-09-24。状态：0.7.0 Windows 预览版已完成本轮实现、自动回归和原生界面检查。具体证据见 [0.7.0 验证记录](validation-0.7.0.md)；Mac、Resolve 工程和公司多人验收仍待对应环境完成。

本文汇总用户已经确认的需求，并确定本轮改进边界。它取代产品文档 1.2 和优化方案 1.3 中已经过时的界面、交互和版本排期；原文保留为设计历史。当前交付能力见 [实施记录](implementation-status.md)，实际运行结果以各版本验证记录为准。这里的验收要求不等于测试已经通过。

## 1. 产品目标和已确认约束

核心流程是：在左侧定位文件夹 → 在当前范围搜索音乐 → 观察每行波形 → 点击任意位置试听 → 比较候选 → 将整首原音乐拖入达芬奇。流畅、可恢复和低占用优先于增加功能数量。

| 项目 | 当前约定 |
| --- | --- |
| 音乐库与人数 | 约 1 TB 公司 NAS / 局域网共享文件夹，6–10 人使用；现有索引只代表已经收录的范围 |
| 平台 | Windows 与 Apple Silicon Mac 是产品目标；当前交付和本轮本地验证限于 Windows |
| Mac 信息 | 用户提供 M4 Pro、48 GB、macOS 27，准确系统和兼容性需对应实机核验 |
| 部署 | 不要求公司增加常开电脑或安装中央服务；客户端退出后其后台任务停止 |
| 搜索 | 左侧按文件夹名称和路径定位真实目录树；右侧检索当前范围音乐；查询使用本机索引 |
| 音频交付 | 整首拖入 Resolve 20 / 21，工程继续引用该电脑能访问的服务器原文件 |
| 共享缓存 | 可以使用独立的可读写共享文件夹；不把多人可写数据库放到 NAS |
| 原件与个人数据 | 不改写、移动、删除音乐；收藏和标签保存在本机；升级保留已有索引和缓存 |
| 界面 | 简洁浅色、清楚的层级和适当留白；默认每行波形，紧凑底部播放条 |
| 情绪理解 | 作为后续增强；目录或标签中的文字分类不能被描述为已经听懂音乐 |

已有音乐库尚未设置共享缓存时，已生成的本机波形不会自动变成公司共享结果。缓存波形也不等于缓存整首音频，首次试听和拖入工程仍可能受到 NAS 速度影响。

## 2. 必须保持的交互和数据契约

- 单击每行波形从对应位置试听。按住移动超过系统拖拽阈值后拖出按下那一行的整首原文件；取消和松开拖动不补发试听，不改变正在播放的曲目。名称拖拽继续保留。
- 拖放只提供复制行为，不向达芬奇提供波形、试听缓存、临时文件或裁切片段的地址。原件不被移动或改写。
- 目录搜索确认后展开祖先、滚动并选中左侧真实节点；定位新目录清空旧音乐关键词。清空左侧搜索框保留已定位位置；导航不打断试听。
- 快速更换关键词、曲目和目录时，旧异步结果不得覆盖新操作。输入法组词期间不提交未完成的音乐查询。
- 本机已缓存波形先显示，过期核验在后台进行；搜索与已有轮廓不等待 NAS。已经确认源文件变化时，不能将旧轮廓继续标成当前准确结果。
- 后台准备可暂停和续跑，损坏文件不能让健康文件永远等待；网络、保存失败和磁盘空间问题有明确状态。失败记录不得伪装成成功或用假波形补齐。

## 3. 0.7 选定范围与验收

下列功能已实现并通过相关自动回归。绘制减负有同条件函数基准，小窗口与实际音乐库已检查；端到端 P95、长时间资源回落和公司多人性能目标仍待测，不以本轮局部基准代替。

| 编号 | 本轮工作 | 必须通过的验收 |
| --- | --- | --- |
| R07-01 | 复用已缓存波形的绘制结果 | 按素材版本、显示尺寸与缩放正确复用；内容或尺寸变化后更新；播放头和进度仍正确；缓存有明确容量上限和淘汰，不随浏览曲目数持续增长 |
| R07-02 | 减少无效界面刷新 | 静止列表不做无意义重绘；播放更新集中于实际变化区域；用相同样本和窗口条件对比 0.6 基线，报告绘制成本及总进程资源，不能只给观感评价 |
| R07-03 | 增量加载更多音乐 | 后续页追加到已有结果，已加载行不整体替换；滚动位置、选择和试听保留；新查询开始后旧翻页结果不能混入；达到加载上限时不将数量冒充完整匹配总数 |
| R07-04 | 明确搜索的等待、空结果与失败 | 三种状态可区分；失败时保留先前结果并说明其不是新查询结果；可重试；错误和迟到结果不清空或覆盖更新的成功查询 |
| R07-05 | 音乐搜索的输入法保护 | 中文组词期间不触发半成品查询；提交后查询正确文本；清空、撤销和快速连续输入仍得到最后意图；快捷键不破坏文本输入 |
| R07-06 | 普通刷新不丢准备成果 | 刷新不全量清空有效本机波形；未变化源文件继续复用；新增或变化条目按真实版本处理；扫描失败、取消保留已有批量游标、成果和异常记录；若此前已提交音乐变化，旧计数转为上次记录并提示待检查，不继续冒充当前完整覆盖 |
| R07-07 | 记住日常使用设置 | 音量、选中后试听及窗口设置重开后恢复；异常设置有安全默认值；窗口不恢复到不可见的屏幕外；保存不写 NAS 原件 |
| R07-08 | 明确范围和缓存数量 | 当前目录的层级与搜索范围清楚，长路径可完整查看；已缓存、参考、失败含义不重叠误导；说明参考包含在已缓存中，暂停与完成可区分 |
| R07-09 | 原生界面整理 | 保持轻量 Qt 列表，不引入模糊或常驻装饰动画；常用窗口及 980 × 640 下主要操作可见；焦点、载入与错误不只依靠颜色；已有波形点击和外拖回归通过 |

刷新是收录变化的操作，不是“删除全部波形后重建”的别名。扫描成功后暂停全库准备，将原计数标为上次记录、等待主动重新检查。失败或取消前没有提交音乐条目的变化时，原准备状态保持不变；若已有一批新增或变化条目成功提交，则同样保留旧游标、计数及异常记录，并标记待检查。事务回滚、未变化文件以及个人标签 / 时长写入，不能被误当作扫描提交了新的音乐版本。

检查新索引时复用有效且源版本匹配的本机波形，不仅因超过 24 小时而重复解码。可见波形超过 24 小时后的后台核验仍保留；刷新触发的核验水位保存到本机续跑状态，重开后继续要求对应缓存后台核验。若需要主动重新检查或重试异常，应在文案和行为上明确区分；失败或取消的扫描不证明源文件已删除。

### 缓存数量的表达

“已缓存”表示已有可展示的轮廓，其中可以包含明确标记的“参考波形”；“参考”是其子集，不再与已缓存相加。“失败”是本次准备未取得可用结果的条目，必须能够查看原因。完成状态不能仅由界面不再增长推断。

0.6.0 现场记录为 59,429 / 59,443 已缓存，其中参考波形 7,072、失败 14。这是当时保存的状态，不是本轮重新扫描结论，也不证明全部参考对应损坏原件。参考状态可能涉及解码容错，原因应以具体文件诊断为准。该历史状态见 [0.6.0 验证记录](validation-0.6.0.md)。

## 4. 性能目标与测试口径

沿用长期体验目标：音乐搜索输入到首屏可交互 P95 ≤ 200 ms，本机缓存约 12–20 个可见行完整呈现 P95 ≤ 150 ms，减少超过 50 ms 的界面停顿。它们是待验证目标；数据库查询返回、绘制函数结束和音频设备出声是不同测量，不可互相替代。

0.7 首先证明新增优化相对 0.6 有可复现收益，并且功能、内存和后台负载没有倒退。测试至少登记版本、数据规模、可见行数、窗口大小、缩放、缓存状态、前后台任务和样本数。报告中位数、P95、最大值及失败数；测试没有覆盖的指标保留待测。

- 绘制：固定波形数据与屏幕宽度，分别测首次绘制、重复绘制和播放进度更新；重复缓存命中不能用首次生成时间替代。
- 内存：新增绘制缓存使用独立的 16 MiB 预算并淘汰旧项，峰值数据仍受现有预算约束；观察连续浏览后的回落，并统计主程序和工作进程，不能将单个缓存预算当成程序总内存硬上限。
- 交互：滚动、翻页和搜索过程中持续试听，检查选择、位置、过期回调及点击定位；静止和后台准备分别测量。
- 数据：自动测试使用隔离目录，真实索引使用一致性备份；不为制造冷缓存而清理公司服务器或修改原音乐。

### 本轮审计基线，仅作测试背景

| 测试背景 | 已观察结果 | 不能据此推导 |
| --- | --- | --- |
| 59,443 条真实本机索引备份的音乐查询 | P50 1.64 ms，P95 4.21 ms | 输入到屏幕显示完成、NAS 首次建库或音频起播时间 |
| 同一索引中 1,414 个目录的查询 | P50 0.61 ms，P95 0.86 ms | 已清点完整 NAS 目录，或左侧树展开与绘制总时间 |
| 6 个 0.6.0 波形工作进程，各用独立本机缓存、同一共享缓存，同时请求一个约 4 MiB 临时 WAV，每个进程读取预算 1 MiB/s | 6 个进程均在 4.06–4.17 秒返回生成成功，并产生 6 个共享波形对象，未协调成单一生成者 | 真实 NAS 上 6 名员工的负载、吞吐或故障率 |

这些基线来自本轮独立审计，完整采样条件和原始记录应由最终验证文档补齐。它们不是 0.7 已交付结果。特别是本机并发测试说明共享输出安全与减少重复读取是两个独立问题，不能声称已有跨电脑单次生成保证。

## 5. 本轮延后，仍保留在产品范围

| 能力 | 后续进入实施的条件 |
| --- | --- |
| 已有库配置 / 更换共享缓存 | 验证库身份、失败回退、权限和已有成果复用，不因接入缓存重建个人数据 |
| 共享清单和生成任务协调 | 验证多客户端崩溃、断网、接管及重复工作比例；不承诺严格只解码一次 |
| 近期试听音频缓存 | 独立验证完整性、磁盘预算、淘汰和拖放原件身份，不能仅有波形就宣称离线试听 |
| 统一后台预算和自动退让 | 统计扫描、指纹、同步、音频缓存和解码的总负载；当前解码限速不是全应用或全公司限速 |
| 磁盘缓存管理、自动目录对账及备份恢复 | 明确所有权与恢复规则，只清理本软件缓存，保留个人数据及业务原件 |
| 情绪理解、相似音乐、BPM / 调性 | 先完成真实样本评估、资源与分发检查；未引入模型前不声称自动听懂音乐 |
| Apple Silicon 软件包 | 在对应 Mac 实际构建并验证主流程、依赖和分发，Windows 测试不能替代 |
| Resolve 20 / 21 兼容 | 分平台、准确补丁版本、媒体池和时间线实际接收整首，保存重开后继续引用原件 |
| 公司多人及竞品比较 | 真实 6–10 人、代表性 NAS 条件和同条件出片对照；另做长时间运行测试 |

## 6. 发布证据与结论边界

本轮回归、绘制基准、原生界面检查与便携包播放检查已记录在 [0.7.0 验证记录](validation-0.7.0.md)。长期指标和延后范围仍保留，不把历史结果或局部函数性能当作未测试场景的证据。

当前不能宣称 Mac、公司多人或 Resolve 工程已经验收，不能宣称“全面超越出片”，也不能把缓存命中解释为音频无需访问服务器。完整文件 URL 和鼠标手势测试证明本应用的交互契约，外部应用是否成功接收仍需在对应工程确认。
