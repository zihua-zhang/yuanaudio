# 源音效管理工具 0.12.1 验证记录

日期：2026-10-27。新增超快不限速档位及全库波形 1 / 2 / 4 首并行。此记录区分 Windows 本机测试与仍待执行的 Mac 验证。

## 实现范围

- 默认仍为 1 MiB/s、1 首；已有 10 MiB/s 选项和个人设置保留。新档位以 0 表示不限速，失败与参考波形重试的“继承当前档位”改用独立的 -1 值，避免把不限速误当作没有设置。
- 多首并行采用最多四个独立解码工作进程，每首仍使用一个解码线程。优先任务与后台任务共同遵守运行数量上限；试听、收录或系统忙时仍遵循用户的剪辑优先设置。
- 1 / 10 MiB/s 按并行上限固定分配；不足设定数量时可能用不满总额度。每个工作进程仍有 256 KiB 初始读取余量。试听、指纹、共享缓存访问不计入该额度，不代表 NAS 全部 I/O 或整家公司总带宽受到硬限制。
- 波形解码结果不会因并行而降采样或换成参考波形。并行仅覆盖全库准备；失败和参考波形复核继续逐首处理，均支持不限速。
- 最多保存四个运行中或等待按顺序登记的任务。先完成后面的文件不推进越过未完成文件的持久化游标；一个很慢的文件可能暂时降低并行利用率。切换速度或并行数量会取消并重新准备未完成任务，已完成本机缓存保留。

## 本机验证

Windows / Qt 6.9.3 / MinGW 13.1 构建成功。最终完整 CTest **27/27 通过，145.03 秒**。日志：`test-output/performance-0.12.1/ctest-release.txt`。此前一轮 27/27 记录也保留；释放额外进程的变更后再次运行了全套回归。

新增/加强的回归覆盖：

- 不限速从 UI 设置、配置恢复、全库准备到两种重试入口均保持为 0。
- 四个真实、不同 PID 的工作进程同时接收任务；10 MiB/s 下每个任务取得四分之一额度。
- 刻意让第 2/3/4 首先结束并注入失败，确认游标不会越过第 1 首，最终成功/失败数量正确。
- 暂停、试听抢占、重启续跑、4 首切换 2 首、不限速切回有限速、索引刷新、手动跳过均保持完整目录计数。
- 可见列表启动新任务不能多开第 5 个解码任务。
- 四首真实 WAV 并行解码与单首串行缓存逐字节一致。
- 全库结束后额外解码进程释放。先复现空闲进程驻留，再增加释放逻辑；暂停和试听让路也会释放这些额外进程。
- 不限速后台任务仍按后台策略等待共享任务，避免被当成试听而过早重复分析；六个客户端的共享缓存及中断恢复回归通过。
- 新控件与设置保存回归通过；在有中文字体的环境检查深浅主题截图，880×640 窗口内控件和说明可读。

先观察到新增行为测试失败，再实现。完整回归另外发现“开始全库时没有立即替换正在运行的旧限速”和“列表优先任务可多开第 5 个进程”两个边界问题；均先复现、修复，再纳入最终回归，没有以放宽断言隐藏问题。

本地合成 WAV 的读取限速回归结果：1 MiB/s 为 2.844 秒，不限速后台为 0.047 秒，波形内容一致。该数据仅证明人工限速被解除，**不是公司 NAS 或 Mac 性能承诺**，也不能当作四核提速倍数。
