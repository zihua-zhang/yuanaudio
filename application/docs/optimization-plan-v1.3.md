## 1. 目标与适用范围

围绕实际配乐流程建立优势：定位文件夹 → 找音乐 → 看波形 → 点任意位置试听 → 连续比较 → 整首拖入达芬奇。检索、交互、起播、资源占用、多人共享、异常恢复和跨平台都纳入验收。

约 1 TB 的公司 NAS 音乐库，现有本机索引 59,443 条，6–10 人使用；支持 Windows 与 Apple Silicon Mac。无需增加常开电脑，保持服务器目录和原音乐不变，达芬奇继续引用服务器原件。情绪识别作为后续增强。

“全面超越出片”作为研发目标，需要逐项对照功能和同条件测试，不能根据技术选型或少数最快结果宣布实现。当前还没有双方同条件的完整性能数据；出片的内部实现也不作推断。未调研确认的其他出片功能，先列差距清单，再决定优先级。

本方案对 v1.2 的修订以此为准：默认每行波形、紧凑播放条，不恢复底部大播放器；文件夹搜索必须定位左侧真实目录树。既有 v1.2 中的大波形默认布局和混合搜索交互不再作为此分支的实施要求。

## 2. 文件夹搜索：在左侧找到、展开、选中

### 2.1 两个明确的入口

| 位置 | 名称 | 作用 |
| --- | --- | --- |
| 左侧目录栏上方 | 定位文件夹 | 按文件夹名称或路径片段查找，跳到目录树中的具体节点 |
| 右侧音乐列表上方 | 搜索音乐 | 在选定范围内搜索音乐名称；个人标签可作为可选条件 |

右侧明确显示范围，例如“短剧配乐 / 伤感 · 包含子文件夹”，旁边可切换“全部素材”。不把文件夹定位混成一大批音乐搜索结果。

### 2.2 具体操作

1. 在左侧输入“伤感”，查询本机目录索引。输入过程中显示简短候选，保留当前目录树和正在播放的音乐。
2. 重名文件夹分别显示所属库和完整路径，例如“配乐 / 古风 / 伤感”和“配乐 / 现代 / 伤感”。匹配文字高亮，完整名称匹配排在前面。
3. 点击候选或按 Enter：展开该文件夹的所有父级，把真实节点滚动到可见区域并选中；候选列表收起，左侧仍是完整目录树。
4. 右侧显示该目录的音乐，默认包含子文件夹，可切换为“仅本层”。文件夹定位不自动播放，也不打断当前试听。
5. 清空定位框仅清除候选条件，保留已定位节点、展开状态和右侧内容。Esc 关闭候选；上、下键选择候选。未确认候选时不反复跳目录。
6. 右侧每首音乐增加“在左侧定位文件夹”。从全库搜索结果可直接返回所属目录，音乐继续播放。
7. 增加目录前进 / 后退，恢复该次目录的搜索范围、关键词和滚动位置；关闭重开后恢复最后的浏览位置。

定位新文件夹时，默认清空右侧音乐关键词，直接展示该目录内容，避免旧关键词造成“文件夹是空的”的误解；浏览后退可恢复此前关键词。定位自己的当前文件夹则不清空。此行为在界面操作说明中明示。

支持中文单字和多字、英文大小写不敏感及多个路径关键词。排序依次考虑文件夹名称完全匹配、前缀匹配、名称包含、路径匹配。匹配规则不改变原始名称和实际文件路径。离线时仍能定位已收录目录，显示上次更新时间；查询本身不等待 NAS。

快捷键：Windows Ctrl+F / Mac Command+F 搜索音乐；增加 Shift 定位文件夹。输入法组词期间不提交半成品查询。

### 2.3 实现与边界

- 新建独立目录索引，保存库身份、目录身份、父级身份、相对路径、显示名称、检索字段和扫描状态。各电脑用自己的挂载根目录解析绝对路径。
- 已有曲目路径先生成目录及祖先记录，可立即使用；之后由增量扫描补齐空目录。未完成完整扫描前，不声称已收录所有空目录。
- 去掉当前目录查询的 10,000 项截断；候选结果分页，继续翻页能找到后续结果，不静默丢失目录。
- 目录树改为按需取子节点，定位时直接取祖先链。查询和目录读取在后台执行，界面只接收有界批次；取消旧查询，不整体清空并重建树。
- 已建库启动时先恢复本机内容，网络核验随后进行。增量更新保留展开、选中、滚动状态；断网或不完整扫描不能当作目录删除。

技术依据：Qt 支持增量获取模型数据，后台准备数据后必须回到模型所属线程提交更新。采用这些能力设计本机索引目录树，不将网络目录遍历放入界面回调。[Qt 模型接口](https://doc.qt.io/archives/qt-6.9/qabstractitemmodel.html)

## 3. 当前瓶颈与处理顺序

以下来自当前代码检查，是本产品的改造依据，并非出片的性能归因。

| 当前情况 | 影响 | 改造 |
| --- | --- | --- |
| 左侧目录从曲目中取 DISTINCT，最多 10,000 个，然后在界面线程重建树 | 大目录启动和刷新有停顿风险；目录可能不全 | 独立目录索引、后台查询、按需加载、局部更新 |
| 磁盘波形命中前，仍核验 NAS 文件信息和头尾指纹 | 已缓存的波形也可能等待服务器 | 本机持久保存素材版本到波形对象的映射，先显示已有轮廓，后台核验 |
| 每个波形任务启动一个子进程，包括磁盘缓存读取 | 多行出现时有重复进程启动开销 | 本机缓存由轻量后台读取器批量读取；缺失时复用一个解码工作进程 |
| 波形内存按约 128 条计数限制 | 长短、声道数和绘制缓存的实际占用不一致 | 改为按字节预算管理，独立统计图形、峰值和音频缓冲 |
| 已播放曲目仍直接从 NAS 再读 | 连续比较同一批曲目反复受网络影响 | 有容量上限的近期试听缓存，优先保障当前音频 |
| 共享生成主要依靠重查和随机等待 | 多人仍可能重复读取同一首 | 可恢复任务领取、租约和不可变结果发布，减少重复工作 |
| 扫描、缓存读取和发布尚无统一预算 | 单个环节限速不能代表应用整体负载 | 一个统一后台调度器，统筹字节、请求数、CPU 时间及取消 |

## 4. 波形：本机优先，按需绘制

### 4.1 显示路径

按“内存 → 本机波形 → 共享波形 → 生成”的顺序获取。列表先出现文字和可点击行，波形补齐不改变行高和滚动位置。

本机索引保存素材版本与波形对象的对应关系。命中本机波形时，立即显示上次核验版本，不再把每行显示串在 NAS 文件检查之后。后台按期限、目录变化和用户刷新触发核验；发现变化立即作废旧映射并替换轮廓。

无法同时承诺“完全不访问 NAS”与“瞬时发现所有同路径替换”。未核验或离线的轮廓应有轻量状态提示。已经确认源文件变化时，不再把旧波形作为当前准确轮廓。拖放和实际播放的可用状态也单独判断。

当前双声道最大精度的单首波形约 16 KiB；59,443 首的纯波形数据约 0.98 GB，另计清单、文件系统开销和旧版本。可以把大量轮廓放在本机磁盘，内存仅保留当前屏幕和有限近期项目。

### 4.2 绘制与滚动

- 只绘制可见行，邻近预取最多一屏；快速滚动期间取消旧请求，滚动停稳后优先当前屏幕。
- 波形点数按实际像素宽度归并，保持峰值，不为 300 像素宽的行反复绘制全部原始桶。
- 底色波形可复用绘制结果，播放时只更新当前行的进度和播放头；暂停或窗口不可见时停止不必要动画。
- 各行共用一个实际播放器，不为每行创建音频设备、播放器或计时器。
- 固定行高，减少重复布局；绘制缓存以尺寸、显示缩放和素材版本为键，并纳入内存预算。Qt 提供等高目录行的性能优化开关。[Qt 树视图](https://doc.qt.io/archives/qt-6.9/qtreeview.html)

这部分无需 AI 模型或独立显卡。真正昂贵的是首次读取、解码和音频传输，不能靠显示波形的快慢代表全部性能。

## 5. 试听：点击优先，重复试听走本机

### 5.1 必须保持的行为

点某行波形 60% 的位置，就从该曲约 60% 开始播放。快速连点时只执行最后一次意图，取消旧加载，避免旧歌迟到后抢播；暂停命令能够取消尚未完成的自动起播。

播放与波形生成互不等待。源文件可读时，即使波形尚未完成，也能先试听。当前位置、载入中、出错、离线等状态要准确区分。

### 5.2 两层优化

1. 保持一个可复用的播放工作进程和有界缓冲，先解决当前文件的读取、定位与第一段音频输出。检测到用户切换，旧任务立即失去优先级。
2. 增加本机“近期试听缓存”，默认预算 10 GiB，可关闭或调整。先缓存实际听过且短暂停留的音乐，不因列表显示而复制几十首；缓存当前源版本的原编码文件，避免强制转码和反复存整首 PCM。

第一阶段只使用已完整写入并校验的音频缓存，临时下载文件不可冒充完整曲目；部分文件边下载边随机定位属于后续单独优化。大于缓存单文件预算的音频继续流式播放，不为缓存耗尽磁盘。

首次打开未缓存曲目仍取决于 NAS 和格式；长 WAV、多声道和 VBR MP3 分别测随机定位。若测量显示现有播放后端本身成为瓶颈，再替换读取/解码路径，不提前为了“更底层”而重写全部播放引擎。

试听来源与素材身份分离：在本机缓存试听，拖放仍输出服务器原文件路径；不可将缓存路径带入达芬奇工程。离线可播放已有缓存，但原件不可访问时明确提示拖入工程的限制。

## 6. 多人共享：复用结果，减少服务器工作

### 6.1 无额外常开电脑

从现有剪辑电脑中，由一台正在运行客户端的电脑承担该素材库的批量预生成。默认不让 10 台电脑各自扫库并解码 1 TB。它退出后保存进度，下次继续，或由其他在线客户端接手；所有客户端关闭时自然停止。

按用户当前需要、常用目录、剩余目录排序，提供“准备这个文件夹”和“准备全部波形”。进度显示完成数、剩余数、失败数与当前速度；暂停、退出、断网后可恢复。

任务领取采用短租约、续期和过期接管，发布使用完整校验的不可变文件。网络中断和时钟差可能导致少量重复计算，不能把文件共享协议包装成绝对只执行一次；重复结果必须安全、可去重，崩溃不得产生可见半成品。

### 6.2 共享内容

- 共享波形和基础元数据，通过有版本的批量清单同步到本机，减少逐首打开小文件的往返。
- 本机数据库独立，搜索完全在本机执行。可复用的目录/曲目快照先验证、落地本机，再合并个人收藏与标签；快照只含共同可访问库的数据，按库隔离。
- Windows 与 Mac 按逻辑库身份和相对路径对应素材，不在共享清单中强制使用 Windows 盘符。
- 不把可写 SQLite 数据库直接放在 NAS 上供多人打开；SQLite 的 WAL 模式要求使用同一主机上的共享内存，不能用于跨主机网络文件系统。[SQLite 官方说明](https://www.sqlite.org/wal.html)
- 新增“设置共享缓存位置”，已有素材库可以接入和更换缓存位置，不要求重新添加整个库。验证库身份和读写能力后生效；切换失败仍能使用已有本机缓存。

### 6.3 初始化成本要透明

全库生成仍要首次读取和解码音频。若按约 1 TB、1 MiB/s 连续读取，单纯传输下限就约 11 天，尚未计解码和小文件往返。因此日常低占用模式与主动批量准备必须分开。

默认“剪辑优先”：低速补齐常用目录。主动选择“准备素材库”时，单台客户端可提高至 10 MiB/s 的起始预算，仍只用一个解码任务，并根据播放延迟和系统繁忙程度退让；实际完成时间通过短样本测得吞吐后估算。高质量多声道或 CPU 解码瓶颈可能使提高带宽没有收益。

## 7. 资源预算与自动退让

以下是初始设计预算，须以 Windows 和 Mac 实测调整；不宣称是操作系统提供的硬限额。统计包含主程序和所有工作进程，不只看界面进程。

| 项目 | 默认方案 / 目标 | 超过预算时 |
| --- | --- | --- |
| 稳态总内存 | 目标 ≤ 350 MiB；常见双声道试听压力峰值目标 ≤ 600 MiB | 先缩减预取和缓存，再暂停后台生成；记录不可控后端占用 |
| 波形数据与绘制缓存 | 合计 64 MiB，按字节淘汰 | 保留可见和当前播放条目，其余最近少用先清理 |
| 应用主动音频缓冲 | 16 MiB 起始预算；解码器内部缓冲另外计入进程总量 | 大文件流式处理；不整首展开到内存 |
| 空闲 CPU | 整机归一化平均 ≤ 1%，窗口静止、无扫描 | 停止无用刷新和频繁轮询 |
| 日常浏览与单曲试听 CPU | 整机归一化 1 秒采样 P95 目标 ≤ 5%，按基线机器单独报告 | 后台降速或暂停；当前试听保持优先 |
| 后台网络流量 | 每台电脑本软件的全部后台任务合计起始 1 MiB/s，允许小额突发 | 动态降速；包括波形、指纹读取、音频缓存复制及上传 |
| 后台并发 | 同时 1 个大读取/解码任务；元数据小批量请求 | 合并重复任务，过期任务取消，不靠排长队续跑 |
| 本机波形磁盘 | 默认 5 GiB | 清理未引用旧版本及冷缓存，可按需恢复 |
| 本机近期试听磁盘 | 默认 10 GiB，临时文件也计入 | 淘汰近期未用文件；当前使用文件暂时保留 |
| 本机剩余空间 | 不足 5 GiB 时暂停新增大缓存 | 搜索及原件流式试听继续工作，显示简短状态 |
| 共享缓存容量 | 初始软预算 50 GiB，可配置 | 仅清理本软件拥有且确认无人使用的过期缓存，不触及原音乐 |

CPU 的“5%”指整机全部逻辑处理器归一化后的占比；同时记录消耗了多少 CPU 核的时间，避免 Windows 与 Mac 显示口径不同。后台预算不强压当前音频的必要码率，否则高码率音频会被自己限速而卡顿。10 台电脑各自同步缓存时，后台总流量仍可能接近 10 MiB/s；库级单一预生成者和客户端错峰同步用于降低峰值，不能把单机预算当作全公司总限速。

默认优先级为：当前试听与定位 → 输入/目录/列表更新 → 可见波形 → 近期缓存 → 增量扫描 → 全库预生成 → 情绪分析。界面操作不与后台读文件排同一串行队列；当前试听也不能被缓存发布占住。

响应时间变差、缓存内存接近预算或系统持续繁忙时，先停止预取、降低后台读取，再暂停扫描与预生成。恢复采用渐进加速和滞后阈值，避免一秒开一秒关。另提供一个明确的“暂停后台准备”开关，用户无需理解调度参数。

缓存目录、索引、个人数据分开管理。清理缓存不删除收藏、标签或原文件；正在播放或被达芬奇引用的原件不属于清理对象。正常退出结束工作进程，无须后台服务常驻。

## 8. 搜索与日常操作的完善

- 名称搜索保留本机索引和取消过期结果；拆分曲名字段、路径字段和标签字段的查询权重，目录定位使用独立查询。
- 先呈现首屏；翻页持续可用，不把当前最多 2,000 条已加载结果误称为完整结果。完整计数异步取得，计数不阻塞可操作结果。
- 中文输入法完成后触发查询；拼音/首字母作为后续可开关增强，通过真实素材命中率验证，避免默认引入大量噪声。
- 固定紧凑布局；所有可操作按钮可见焦点，播放/载入/错误不仅靠颜色表示。Windows 高 DPI 与 Mac Retina 独立检查。
- 收藏、标签保存通过后台短事务，不因 NAS 断开而失败；扫描结果合并、时长回写、批量清单导入都不在界面线程执行。
- 用户选中文件名拖放时不误触波形跳转；加载波形和写缓存不得阻塞原件拖放。

## 9. 情绪理解放在核心流畅度达标之后

先支持人工标签和目录文字辅助分类，标明来源。真正的自动情绪分析再提供“紧张、悲伤、温暖、悬疑、史诗”等可多选标签，并允许人工修正；不能把文件夹叫“悲伤”当作模型听懂了音乐。

模型分析默认关闭，由一台客户端批量处理并共享结果，日常搜索仅查本地标签，不在每次输入时运行模型。首选离线分析；如果以后引入外部服务，另行明确音频是否出网、费用和授权。

在公司样本上由使用者评估标签可用率和找歌耗时，再决定是否发布“相似音乐”和节奏、能量筛选。准确性与资源预算不合格时，不挤入核心版本。

## 10. 验收指标：体验与资源一起通过

基准数据：现有约 6 万首真实库；再以合成元数据扩展到 10 万条曲目、2 万个目录，验证规模。实际目录数未知，2 万是测试规模，不是当前清点结果。

所有延迟报告中位数、P95 和失败数。P95 指 95% 的操作在该时间内完成；不能拿数据库查询时间代替输入到界面可操作的总耗时。

| 操作 | 初始目标 | 计时口径 / 条件 |
| --- | --- | --- |
| 已建库启动可搜索 | P95 ≤ 2 s | 点击启动至本机目录、搜索可交互，不等 NAS |
| 文件夹候选出现 | P95 ≤ 150 ms | 最后一次输入至候选可选，含防抖；输入法按提交计时 |
| 左侧目录定位 | P95 ≤ 100 ms | 确认候选至祖先展开、节点滚动和选中完成；本机目录已索引 |
| 音乐搜索首屏 | P95 ≤ 200 ms | 输入至首批 50 条可交互，含防抖；不等波形或总数 |
| 本机缓存整屏波形 | P95 ≤ 150 ms | 约 12–20 个可见行，含本机读取和首个完整绘制；共享命中另计 |
| 滚动和切换 | 滚动更新 P95 ≤ 16.7 ms；避免单次 > 50 ms 的界面停顿 | 测事件循环和实际呈现，不用空闲帧稀释结果 |
| 已缓存音频点击出声 | P95 ≤ 150 ms | 常见双声道格式、任意位置；音频设备输出测量 |
| NAS 未缓存音频点击出声 | P95 ≤ 1 s | 健康有线千兆基准，格式、长度和 NAS 负载分别报告 |
| 原件拖拽准备 | P95 ≤ 100 ms | 从拖动成立到原件地址交付；达芬奇导入耗时另计 |
| 稳定性 | 连续 8 小时混合操作无崩溃、串音和持续内存增长 | 包含快速切曲、扫描、网络中断及恢复 |

播放验收同时记录“解码后首个音频缓冲”和“设备输出”。使用已知音调的测试音频及回环录音对时，避免开头静音被误判为载入慢；真实歌曲另测随机定位误差。仅出现“播放中”状态不算出声。

### 对照出片的方法

1. 同一电脑、同一 NAS、相同文件和目录范围；先登记双方版本、配置、音频格式及正在运行的负载。
2. 固定至少 50 个真实关键词、重名目录和多级路径；播放选择不少于 20 首，合计至少 200 次定位操作。
3. 区分内存命中、本机磁盘命中、仅共享波形命中、尚未生成四种状态；音频缓存状态独立记录。首次安装与正常日常使用分别报告，不能让一方热缓存、一方冷缓存却称同条件。
4. 使用交错次序重复测试，标注操作系统/NAS 缓存状态是否可控；不为制造冷缓存而清理生产服务器或系统缓存。
5. 单人达标后做 6–10 客户端验证。单机开 10 个模拟客户端只能验证协议，不能代替真实多人网络表现。
6. 同时运行具有代表性的达芬奇工程，对比只有达芬奇与增加素材库软件时的播放掉帧、导出耗时。导出耗时增加目标 ≤ 3%，需重复测量并考虑自然波动；达不到就收紧后台预算。
7. 输出分项比较：更快、相当、落后、尚未测。差异小于自然波动时记为相当；不得用平均值掩盖明显的卡顿尾部或错误。

发布门槛是主要配乐流程无关键能力缺口、性能目标通过、异常恢复可靠、资源不挤占剪辑。只有同条件结果支持，才对外表述相应维度已超过出片；尚未覆盖的功能和平台必须保留待测标记。

## 11. 分阶段交付

| 阶段 | 交付内容 | 进入下一阶段的条件 |
| --- | --- | --- |
| 0.4：目录定位与测量 | 双搜索入口、独立目录索引、左侧展开定位、范围清晰、无 10,000 截断、浏览状态保留；埋点统计端到端延迟和进程总占用 | 重名、深层、中文、空目录、离线、2 万目录测试通过，定位不会打断播放 |
| 0.5：波形本机直达 | 持久映射、后台核验、复用工作进程、字节预算、共享缓存设置、可暂停预生成、共享清单与任务协调 | 缓存命中不等待 NAS；源变化不永久显示旧波形；并发、崩溃、容量回收通过 |
| 0.6：试听与资源控制 | 近期音频缓存、统一调度、自动退让、慢网络恢复、首个缓冲与出声测量 | 连续快速切曲不串音；拖放始终为原件；缓存容量和总资源指标通过 |
| 正式候选版：双平台与对照 | Windows / Apple Silicon 包、真实 Resolve 整首拖放、6–10 人 NAS 验证、同条件出片对照、8 小时耐久 | 公司实际工作流程和资源预算通过，公开剩余限制 |
| 后续增强 | 情绪识别、相似音乐、节奏/能量筛选 | 核心体验保持达标，分类效果通过用户样本验收 |

建议第一优先级是 0.4，再做 0.5。前者解决现在明确不符合操作习惯的目录搜索，后者移除“已经缓存还等 NAS”的主要等待路径。音频缓存随后补齐点击起播；情绪模型最后加入。

正式发包采用独立版本目录。由于 0.2 与 0.3.1 当前共用本机数据位置，出现不兼容的数据结构升级前必须解决共写风险：新分支使用独立数据配置，通过 SQLite 一致性备份迁移一次收藏和索引，保留旧配置可回退；不直接复制正在写入的数据库文件，也不允许新旧版本悄悄同时修改同一套不兼容数据。

本次产出仅为方案，未启动全库扫描、批量预缓存或情绪分析，也未实施上述待开发功能。现有可运行版本仍为 0.3.1。Mac 实机、达芬奇工程内拖放和公司多人对照仍需在对应环境完成，不能由本机自动测试替代。
