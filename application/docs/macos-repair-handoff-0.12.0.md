## 执行目标

在原 M 系列 Mac 上，让源音效管理工具实际加载带有此修复的 Qt Cocoa 运行时，并验证之前触发闪退的原生无障碍路径。保留同一套 0.12.0 产品源码与现有功能。

1. 保留上一轮未修复的应用、DMG、日志、源码和插件哈希作对照。工作在独立目录，不覆盖已安装的软件，不修改同事的全局 Qt、其他工程或系统安全设置。
2. 读取包内核验记录、崩溃报告与官方补丁，确认现有工程仍是 Qt 6.11.2 和原始 0.12.0 产品代码。
3. 优先在同版本 Qt 6.11.2 上回移正式补丁，以减少无关变化。获取官方完整 qtbase v6.11.2 源码，核对版本并先执行 `git apply --check`，再应用补丁；记录源码来源、提交和文件哈希。
4. 使用同一 Mac SDK、Release、arm64 和匹配的 Qt 配置，重建需要的 Cocoa 平台插件或 Qt 运行时。根据现有 Qt 构建工具判断可行方式；SDK 安装包不一定包含单独重建插件所需的全部内部构建文件，不能只把几个 `.mm` 文件当作独立库直接编译。
5. 若单独重建插件，必须确保 Qt 精确版本、私有 ABI、配置和架构匹配，记录其依赖检查和实际加载路径。不要把其他 Qt 版本的插件直接替换到 6.11.2 中。若必须重建整套依赖，记录原因、全部版本与构建配置，并重新验证。
6. 也可以使用经官方源码/构建记录确认已含此提交的兼容发布版本，但需要明确证据；仅凭版本号更大不够。未经验证不要自动升级整套依赖。

若原工程已不在，可从 `original-source/` 中的未修改 0.12.0 ZIP 恢复独立工程，再检查并应用 `application-fix/source-changes.patch`；该补丁只是上轮已经验证的测试路径修正，与 `qt-upstream/` 的 Qt 运行时补丁是两回事。已有此修正的工程不要重复应用。

不要通过关闭无障碍、让列表不再暴露选中项、移除表格/目录、停止所有自动化客户端、修改二进制机器码或捕获崩溃信号来交差。界面仍需支持正常的无障碍查询和原有操作。

## 打包时特别注意

原 `scripts/prepare-macos.sh` 固定选择 `.tools/Qt/6.11.2/macos`，原 `macdeployqt` 也会复制所选 Qt 目录中的插件。只改一份源码或只替换一次 app 内插件，后续重新部署可能又恢复成未修复版本。

- 给本工程显式选择修复后的 Qt 安装/部署目录，或实现有校验、有记录的项目内插件部署步骤；相关脚本改动必须回传。
- 使用 `scripts/build-macos.sh` 的 Qt 目录参数时，确保相应 CMake、Ninja、Python 依赖可用。原脚本会执行完整构建和打包检查，不应为了通过而删去步骤。
- 在最后一次部署之后，记录 app 内 `libqcocoa.dylib` 的 SHA-256、UUID、arm64、依赖和版本来源，确认实际运行的就是该文件。
- 任何 app 内容修改必须在最终签名之前完成；之后重新执行签名校验、解码回归、DMG 制作和镜像校验。不能复用旧版的签名结果或 `.sha256`。
- 未提供 Developer ID 和公证配置时继续如实标记 ad hoc 内部预览，不要关闭 Gatekeeper。

保留产品版本 0.12.0，并用回传包名中的 `Mac修复复测` 及构建报告区分本轮产物；不要擅自覆盖上轮 DMG，也不要仅改文件名冒充新构建。最终正式发布版本号由原开发端统一安排。

## 必须完成的验证

### 自动与原生回归

- 本软件完整 CTest：当前应为 27 项，记录最终通过数和日志，不跳过失败。
- 构建、运行补丁新增的 Qt 原生 `tableViewSelectionAfterModelChange` 回归，以及该原生测试套件相关表格测试。需要 Accessibility 授权时让同事在系统界面授予当前测试工具，不能把未授权的空结果算通过。
- 若这台机器无法运行官方测试，必须说明原因并做同等语义的原生 AX 查询测试：选中单元格、改变模型行数、处理事件之后读取选中子元素，检查返回成功、选中内容正确且可访问接口仍有效。仅运行 `QAccessible` 层测试或截图不等价于 Cocoa 原生 AX 测试。
- 在可控测试实例上验证旧插件可复现、新插件不再出现问题；如果旧版无法稳定复现，记录采样次数和差异，不能声称已经形成严格对照。

### 本软件交互

使用独立 `--data-dir` 和上轮的六段合成音频，保留源文件前后 SHA-256：

1. 选中曲目后，反复读取原生无障碍树及选中子元素；空列表和有选中项两种状态都覆盖。
2. 在两个库之间切换，搜索导致列表从多行变为单行，再清空搜索；每次变化后读取原生树。
3. 左侧文件夹搜索“雨夜”，回车定位、展开、返回；核对目录真的定位完成。
4. 反复打开设置、切换设置导航、切换浅/深色、关闭设置，并再次读取主界面无障碍树。
5. 在测试文件上仅从列表移除、恢复收录，再移除整个测试库并重新添加。另一测试库和全部测试原文件保持。
6. 点击波形定位、播放/暂停、拖动底部进度、音量和设置持久化。请人确认实际能听到声音；无人听音时仍写未确认。

建议至少 30 次带选中项的无障碍读取、20 次模型/目录/设置变化后的读取，记录次数、操作顺序、AX 返回值、进程状态及崩溃报告目录变化。测试数量不代替正确断言，不能通过返回空的选中项来“避免闪退”。

实际公司 SMB 缓存初始化/复用及达芬奇原文件直拖，在明确的测试共享和空白测试工程中补验；无法测试就继续列为未测，不影响清楚报告本轮闪退修复结果。
